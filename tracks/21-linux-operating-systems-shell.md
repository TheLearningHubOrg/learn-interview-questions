## Part 1: Linux Process Internals & Lifecycle (1 - 15)

### 1. What happens during Process Creation: `fork()`, `vfork()`, `clone()`, and `execve()`?
**In Simple Words:**
- **`fork()`**: Creates a child process by duplicating the parent's address space. It uses **Copy-On-Write (COW)**: the child shares the parent's physical memory pages in read-only mode until either process writes to a page, triggering an isolated memory page copy.
- **`execve()`**: Replaces the current process image, memory, stack, and heap with a new executable program, keeping the same Process ID (PID) and open file descriptors (unless `O_CLOEXEC` is set).
- **`clone()`**: The underlying Linux system call powering both processes and threads. Flags control what is shared (`CLONE_VM` shares memory space for threads, `CLONE_NEWPID` creates isolated PID namespaces for Docker containers).

### 2. Zombie Processes vs. Orphan Processes: Causes, Dangers, and Remediation.
**In Simple Words:**
- **Zombie Process (`Z` state in `ps`)**: A child process that has completed execution (`exit()`), but its entry in the OS process table remains because the parent has not yet read its exit status code via `wait()` or `waitpid()`.
  - *Danger*: Zombies consume no CPU or RAM, but exhaust the finite pool of available **PIDs**.
  - *Fix*: You cannot kill a zombie with `kill -9` (it is already dead). You must kill the parent process so the zombie is reparented to `PID 1` (init/systemd), which automatically calls `wait()` to reap it.
- **Orphan Process**: A running process whose parent died before it finished. It is immediately adopted by `PID 1` (systemd), which handles its cleanup upon exit.

### 3. Linux Process States: R, S, D, T, and Z.
**In Simple Words:**
- **`R` (Running / Runnable)**: Actively executing on CPU or waiting in the CPU run queue.
- **`S` (Interruptible Sleep)**: Waiting for an event or I/O (e.g. disk read, socket packet, timer). Responds to signals.
- **`D` (Uninterruptible Sleep / Disk Sleep)**: Waiting on hardware I/O (NFS lock, disk device). **Cannot be killed by `kill -9`**! If stuck, usually indicates failing hardware, dead NFS mount, or kernel driver deadlock.
- **`T` (Stopped)**: Paused by a signal (`SIGSTOP`, `Ctrl+Z`).
- **`Z` (Zombie)**: Terminated, waiting for parent to reap.

### 4. Linux Signals: `SIGTERM` (15) vs. `SIGKILL` (9) vs. `SIGINT` (2) vs. `SIGHUP` (1).
**In Simple Words:**
- **`SIGTERM` (15 - Default kill)**: Graceful termination request. Can be caught, blocked, or handled by the process to flush buffers, finish active requests, and close database connections.
- **`SIGKILL` (9)**: Immediate hard kill executed directly by the kernel. **Cannot be caught, blocked, or ignored**. The process is annihilated instantly without opportunity to clean up.
- **`SIGINT` (2)**: Interrupt signal generated by pressing `Ctrl+C` in terminal.
- **`SIGHUP` (1)**: Hangup signal. Sent when terminal disconnects; modern daemons (Nginx, PostgreSQL) use `SIGHUP` to reload configuration files without dropping active connections.

### 5. Inter-Process Communication (IPC): Pipes, Unix Domain Sockets, Shared Memory, and Message Queues.
**In Simple Words:**
1. **Anonymous Pipes (`|`)**: Unidirectional data stream between parent and child processes.
2. **Named Pipes (FIFO)**: File system entity (`mkfifo /tmp/mypipe`) enabling bidirectional streaming between unrelated processes.
3. **Unix Domain Sockets (UDS)**: High-performance bidirectional IPC on the same host. Bypasses the network stack (no checksums, no routing, no TCP overhead), delivering **2–3x lower latency** than localhost TCP loopbacks.
4. **Shared Memory (`shmget` / `mmap`)**: The fastest IPC mechanism. Multiple processes map the same physical RAM pages into their address spaces. Requires synchronization (semaphores/mutexes) to prevent race conditions.

## Part 2: Linux Virtual Memory, Page Cache & File Systems (16 - 30)

### 6. How does Linux Virtual Memory work (Page Tables, TLB, Page Faults, and Swap)?
**In Simple Words:**
Each process operates in an isolated virtual address space (0 to $2^{64}-1$ on 64-bit systems):
- **Memory Pages**: Physical RAM is divided into fixed blocks (standard is **4KB**).
- **Page Table**: Managed by the OS and Memory Management Unit (MMU) to translate virtual addresses to physical RAM frames.
- **TLB (Translation Lookaside Buffer)**: Hardware CPU cache storing recent virtual-to-physical address translations for single-cycle lookups.
- **Major Page Fault**: Process accesses a page not currently in physical RAM (swapped out to disk or memory-mapped file). The OS stalls the thread and loads the 4KB block from disk into RAM.
- **Minor Page Fault**: Page exists in physical memory (e.g. shared library), but the process's page table hasn't mapped it yet. Resolved in CPU registers without disk I/O.

### 7. What is the Linux OOM (Out Of Memory) Killer, and how does `oom_score_adj` work?
**In Simple Words:**
Linux allows memory **overcommitting** (promising more RAM to processes than physically available, betting processes won't use all allocated memory at once).
When physical RAM and swap are completely exhausted:
1. The kernel activates the **OOM Killer**.
2. Calculates an `oom_score` (0–1000) for every process based on memory usage percentage.
3. Kills the process with the highest score to save the operating system from a kernel crash.
4. **Tuning**: You can protect critical daemons (Docker, SSHD) by writing `-1000` into `/proc/<pid>/oom_score_adj` (meaning "never kill").

### 8. Explain File Descriptors (`0, 1, 2`), the System File Table, and `ulimit -n`.
**In Simple Words:**
In Linux, "Everything is a file": regular files, directories, network sockets, pipes, and devices are accessed via integer **File Descriptors (FDs)**:
- `0`: `stdin` (Standard Input)
- `1`: `stdout` (Standard Output)
- `2`: `stderr` (Standard Error)

Each process has a private file descriptor table pointing to the kernel's open file table and inode table.
**`ulimit -n`**: Limits maximum open file descriptors per process (default is often 1024). High-concurrency servers (Nginx, Redis) must increase this to `65535` or `1000000` in `/etc/security/limits.conf` to prevent `too many open files` socket errors.

### 9. What is an Inode, and what is the difference between Hard Links and Soft (Symbolic) Links?
**In Simple Words:**
An **Inode (Index Node)** stores metadata about a file: file size, owner UID, permissions, timestamps, and pointers to disk blocks (does NOT store the filename or data content).

- **Hard Link**: Another filename entry in a directory pointing directly to the **same Inode number**.
  - Shares the same disk blocks.
  - Deleting the original file does NOT delete the data; data is only freed when the inode's link count reaches zero.
  - Cannot link directories or span across different filesystem partitions.
- **Soft Link (Symlink - `ln -s` )**: A separate independent file with its own inode whose data block contains the string path to the target file.
  - Can cross filesystem boundaries.
  - If the target file is deleted, the symlink becomes a broken / dangling pointer.

### 10. How does the Linux Page Cache work, and what are Dirty Pages?
**In Simple Words:**
Linux uses all unused physical RAM as a **Page Cache** to cache disk reads and writes:
- Reading a file loads its blocks into the page cache; subsequent reads are served from RAM at gigabytes/sec.
- When an application writes, bytes are written to page cache memory immediately, marked as **Dirty Pages**, and the write syscall returns.
- Background kernel flusher threads (`kswapd`, `flush`) asynchronously sync dirty pages to physical disk.
- To inspect page cache: `free -h` (look at `buff/cache`).
- To force an immediate flush: run `sync` or write `3` to `/proc/sys/vm/drop_caches`.

## Part 3: Systemd, Namespaces & Production Administration (31 - 50)

### 11. What is Systemd, and how do Unit Files, Cgroups, and Journald work?
**In Simple Words:**
**Systemd** is the modern init system and service manager (`PID 1`) on Linux:
- **Unit Files (`.service`)**: Declarative configuration specifying how to start, monitor, restart, and sandbox background services.
- **Control Groups (cgroups)**: Caps and tracks resource utilization (CPU, RAM, disk I/O, network) for a collection of processes.
- **Journald (`journalctl`)**: Centralized binary logging daemon capturing logs from stdout/stderr, syslog, and the kernel.

```ini
# /etc/systemd/system/myapp.service
[Unit]
Description=High-Throughput Go Backend API
After=network.target

[Service]
ExecStart=/opt/myapp/bin/server
Restart=always
RestartSec=5
User=appuser
LimitNOFILE=65536
MemoryMax=2G
CPUQuota=200%

[Install]
WantedBy=multi-user.target
```

### 12. Linux Namespaces: How do they form the foundation of Docker Containers?
**In Simple Words:**
Containers are NOT virtual machines; they are ordinary Linux processes isolated by kernel **Namespaces**:
1. **PID Namespace**: Isolates process IDs (the container sees itself as `PID 1`).
2. **NET Namespace**: Isolates network interfaces, IP addresses, and routing tables.
3. **MNT (Mount) Namespace**: Isolates filesystem mount points (rootfs).
4. **IPC Namespace**: Isolates shared memory, semaphores, and message queues.
5. **UTS Namespace**: Isolates hostname and domain name.
6. **USER Namespace**: Maps container root (`UID 0`) to an unprivileged user on the host.

### 13. Essential Troubleshooting CLI Toolkit: `lsof`, `netstat / ss`, `strace`, and `tcpdump`.
**In Simple Words:**
- **`ss -tulpn`**: Fast socket statistics showing all listening ports and the exact PID owning each port.
- **`lsof -p <PID>`**: Lists all open files, sockets, and libraries held by a process.
- **`strace -p <PID>`**: Intercepts and logs every system call made by a running process in real-time. Crucial for debugging hung processes.
- **`tcpdump -i eth0 port 80 -w capture.pcap`**: Captures raw network packets for deep inspection in Wireshark.

### 14. Essential Shell Scripting: Error Handling with `set -euo pipefail`.
**In Simple Words:**
In standard bash, scripts continue executing even if a command fails, leading to catastrophic data loss.
The golden header for production bash scripts:
```bash
#!/usr/bin/env bash
set -euo pipefail

# -e : Exit immediately if any command exits with a non-zero status.
# -u : Treat unset variables as an error and exit immediately.
# -o pipefail : The return value of a pipeline is the status of the LAST command to exit with non-zero.
```

### 15. Senior Systems Engineer Conclusion: Linux Philosophy.
**In Simple Words:**
1. Master the `/proc` virtual filesystem: `/proc/cpuinfo`, `/proc/meminfo`, `/proc/<pid>/status`.
2. Treat cgroups and namespaces as fundamental primitives for resource governance.
3. Always verify file descriptor limits, socket reuse settings, and memory overcommit configurations before deploying high-scale distributed applications.
