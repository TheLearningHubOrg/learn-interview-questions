### 1. What happens during Process Creation: `fork()`, `vfork()`, `clone()`, and `execve()`?
**In Simple Words:**
- **`fork()`**: Creates a child process by duplicating the parent's address space. It uses **Copy-On-Write (COW)**: the child shares the parent's physical memory pages in read-only mode until either process writes to a page, triggering an isolated memory page copy.
- **`execve()`**: Replaces the current process image, memory, stack, and heap with a new executable program, keeping the same Process ID (PID) and open file descriptors (unless `O_CLOEXEC` is set).
- **`clone()`**: The underlying Linux system call powering both processes and threads. Flags control what is shared (`CLONE_VM` shares memory space for threads, `CLONE_NEWPID` creates isolated PID namespaces for Docker containers).

### 3. Linux Process States: R, S, D, T, and Z.
**In Simple Words:**
- **`R` (Running / Runnable)**: Actively executing on CPU or waiting in the CPU run queue.
- **`S` (Interruptible Sleep)**: Waiting for an event or I/O (e.g. disk read, socket packet, timer). Responds to signals.
- **`D` (Uninterruptible Sleep / Disk Sleep)**: Waiting on hardware I/O (NFS lock, disk device). **Cannot be killed by `kill -9`**! If stuck, usually indicates failing hardware, dead NFS mount, or kernel driver deadlock.
- **`T` (Stopped)**: Paused by a signal (`SIGSTOP`, `Ctrl+Z`).
- **`Z` (Zombie)**: Terminated, waiting for parent to reap.

### 4. Linux Signals: `SIGTERM` (15) vs. `SIGKILL` (9) vs. `SIGINT` (2) vs. `SIGHUP` (1).
**In Simple Words:**
- **`SIGTERM` (15 - Default kill)**: Graceful termination request. Can be caught, blocked, or handled by the process to flush buffers, finish active requests, and close database connections.
- **`SIGKILL` (9)**: Immediate hard kill executed directly by the kernel. **Cannot be caught, blocked, or ignored**. The process is annihilated instantly without opportunity to clean up.
- **`SIGINT` (2)**: Interrupt signal generated by pressing `Ctrl+C` in terminal.
- **`SIGHUP` (1)**: Hangup signal. Sent when terminal disconnects; modern daemons (Nginx, PostgreSQL) use `SIGHUP` to reload configuration files without dropping active connections.

### 6. How does Linux Virtual Memory work (Page Tables, TLB, Page Faults, and Swap)?
**In Simple Words:**
Each process operates in an isolated virtual address space (0 to $2^{64}-1$ on 64-bit systems):
- **Memory Pages**: Physical RAM is divided into fixed blocks (standard is **4KB**).
- **Page Table**: Managed by the OS and Memory Management Unit (MMU) to translate virtual addresses to physical RAM frames.
- **TLB (Translation Lookaside Buffer)**: Hardware CPU cache storing recent virtual-to-physical address translations for single-cycle lookups.
- **Major Page Fault**: Process accesses a page not currently in physical RAM (swapped out to disk or memory-mapped file). The OS stalls the thread and loads the 4KB block from disk into RAM.
- **Minor Page Fault**: Page exists in physical memory (e.g. shared library), but the process's page table hasn't mapped it yet. Resolved in CPU registers without disk I/O.

### 7. What is the Linux OOM (Out Of Memory) Killer, and how does `oom_score_adj` work?
**In Simple Words:**
Linux allows memory **overcommitting** (promising more RAM to processes than physically available, betting processes won't use all allocated memory at once).
When physical RAM and swap are completely exhausted:
1. The kernel activates the **OOM Killer**.
2. Calculates an `oom_score` (0–1000) for every process based on memory usage percentage.
3. Kills the process with the highest score to save the operating system from a kernel crash.
4. **Tuning**: You can protect critical daemons (Docker, SSHD) by writing `-1000` into `/proc/<pid>/oom_score_adj` (meaning "never kill").

### 8. Explain File Descriptors (`0, 1, 2`), the System File Table, and `ulimit -n`.
**In Simple Words:**
In Linux, "Everything is a file": regular files, directories, network sockets, pipes, and devices are accessed via integer **File Descriptors (FDs)**:
- `0`: `stdin` (Standard Input)
- `1`: `stdout` (Standard Output)
- `2`: `stderr` (Standard Error)

Each process has a private file descriptor table pointing to the kernel's open file table and inode table.
**`ulimit -n`**: Limits maximum open file descriptors per process (default is often 1024). High-concurrency servers (Nginx, Redis) must increase this to `65535` or `1000000` in `/etc/security/limits.conf` to prevent `too many open files` socket errors.

### 9. Linux Virtual Memory: Page Faults, Resident Set Size (RSS), and Virtual Size (VSZ).
**In Simple Words:**
Every Linux process operates in its own 64-bit virtual address space:
- **VSZ (Virtual Size)**: Total memory the process has allocated (including mapped shared libraries and allocated but untouched memory pages).
- **RSS (Resident Set Size)**: Actual physical RAM occupied by the process.
- **Page Fault**: Occurs when a process accesses a virtual address not currently mapped to physical RAM.
  - *Minor Fault*: Page is already in memory (e.g. shared library loaded by another process).
  - *Major Fault*: Page must be read from disk (I/O penalty).

### 10. Linux Signals: SIGTERM (15) vs. SIGKILL (9) vs. SIGINT (2).
**In Simple Words:**
- **SIGINT (2)**: Triggered by `Ctrl+C`. Can be caught, blocked, or ignored.
- **SIGTERM (15)**: Graceful termination request. The process catches the signal, drains active HTTP connections, commits open DB transactions, closes file handles, and exits cleanly.
- **SIGKILL (9)**: Immediate hard kill executed by the Linux kernel. Cannot be caught, blocked, or ignored. The process terminates immediately without running clean-up handlers.

### 11. Linux IPC: Unix Domain Sockets vs. Named Pipes (FIFOs) vs. Shared Memory.
**In Simple Words:**
1. **Unix Domain Sockets**: Fast, bidirectional IPC using standard socket APIs within the same OS kernel. Avoids TCP checksums, sequence tracking, and network loopback overhead (2x faster than TCP localhost).
2. **Pipes / FIFOs**: Unidirectional byte stream between processes.
3. **Shared Memory (`shm_open`, `mmap`)**: Fastest IPC mechanism. Both processes map the same physical RAM pages into their address spaces, allowing data exchange with zero kernel context switches.

### 12. Linux Inodes, Hard Links vs. Soft (Symbolic) Links, and File Descriptors.
**In Simple Words:**
- **Inode**: Metadata record on disk storing file permissions, owner, file size, timestamps, and pointers to disk data blocks (does NOT store the file name).
- **Hard Link**: Another directory entry pointing to the exact same inode number. Deleting one hard link does not delete the file data as long as `inode.link_count > 0`.
- **Soft Link (Symlink)**: A tiny file storing the textual path string to another target file.
